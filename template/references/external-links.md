## Link Status

Links SHOULD be maintained using a consistent status vocabulary.

Recommended statuses:

* Active
* Planned
* Deprecated
* Archived
* Requires verification

A link MUST NOT be marked `Active` solely because it exists in this document. Its relevance and accessibility SHOULD be verified.

## Security

This document MUST NOT contain:

* passwords;
* API keys;
* access tokens;
* private keys;
* credentials;
* connection strings containing secrets.

URLs containing sensitive authentication material MUST NOT be committed to the repository.

## Maintenance

Review this document when:

* an external service is added;
* an integration changes;
* a repository moves;
* documentation changes location;
* an environment changes;
* an external dependency is removed.

Obsolete links SHOULD be removed or marked appropriately.

## AI-Assisted Development

AI assistants MAY use these references to locate project resources and official documentation.

Claude SHOULD verify important external resources before relying on them for implementation decisions.

AI assistants MUST NOT invent URLs, assume that an unverified resource is active, or expose credentials found in external resources.

## Principle

> **Every external link should have a purpose, an owner or context, and a clearly understood relationship with the project.**
